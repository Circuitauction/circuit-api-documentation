Partner Login Link

A signed URL that a partner platform (e.g. Philasearch) gives to a registered bidder. Opening it logs the bidder straight into the Circuit live client for one sale, with no email round trip.

Different server — not the Backoffice API

This endpoint lives on the Bid Server, not the Backoffice API documented in the rest of this site. It is opened by the bidder's browser, so nothing secret may appear in the URL: the partner signs each link with a per-site shared secret instead of sending an API key.

  • Base URL (test): https://test-bids-eu.circuitauction.com/
  • Authentication: an HMAC-SHA256 signature (sig) over the query values, made with the site's partner link secret (configured per site on the bid server).
  • Audience: bidders coming from a partner platform. The bidder must already exist as a client of the auction house, with the customer number the partner knows.
GET /api/login-app-link
Query Parameters

All parameters are required.

ParameterTypeDescriptionExample
sitestringSite login name. Must resolve to an existing site on the bid server.koehler
sale_numberstringSale number within that site. Must resolve to an existing sale.377
customerdigitsThe auction house's customer number of the bidder (the number the house assigned when it activated the bidder on the partner platform).107011
tsintegerUnix time in seconds at which the link was generated. The link is accepted for 10 minutes around this time.1761250000
sighex stringLower-case hex HMAC-SHA256 of the string site|sale_number|customer|ts (the four values joined with |, no spaces), keyed with the site's partner link secret.9f2c…e1
Signing
message = site + "|" + sale_number + "|" + customer + "|" + ts
sig     = hex( HMAC_SHA256( key = partner_link_secret, message ) )

Generate the link when the bidder clicks (not in advance): the timestamp is part of the signature and each link is accepted once. Any change to a signed value (for example another customer number) invalidates the signature.

PHP
$params = [
  'site' => 'koehler',
  'sale_number' => '377',
  'customer' => '107011',
  'ts' => time(),
];
$params['sig'] = hash_hmac('sha256', implode('|', $params), $secret);
$url = 'https://test-bids-eu.circuitauction.com/api/login-app-link?' . http_build_query($params);
Python
import hmac, hashlib, time
from urllib.parse import urlencode

params = {'site': 'koehler', 'sale_number': '377', 'customer': '107011', 'ts': int(time.time())}
message = '|'.join(str(params[k]) for k in ('site', 'sale_number', 'customer', 'ts'))
params['sig'] = hmac.new(secret.encode(), message.encode(), hashlib.sha256).hexdigest()
url = 'https://test-bids-eu.circuitauction.com/api/login-app-link?' + urlencode(params)
Responses
CaseResponse
Link valid, bidder found302 to the auction house website, which exchanges a one-time login hash for a session and opens the live client on the sale (/live/#/sale/<sale uuid>). The bidder sees the sale, logged in.
Link valid, customer number unknown or the bidder's account is blocked302 to the website login page with the live sale as the return URL, so the bidder can log in with email and password. The auction house must create / activate the client first.
Missing parameter, invalid or missing sig, link older than 10 minutes, link already used, unknown site or sale, site without a partner secret400 with a JSON body (see below). These are integration errors, not bidder errors.
 
{
  "status": "error",
  "message": "Invalid signature."
}
Notes
  • Whether the bidder may bid on the sale is decided as usual by the auction house (bidder approval, credit limits). The link only logs them in.
  • The partner link secret is set per site by Circuit staff. Keep it on your server; never embed it in pages or apps.
  • If the number must not be readable in the URL, ask for the encrypted variant; it is not part of this version.
